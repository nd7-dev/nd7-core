Harness, not prototype: `bench.py` (10), `pty_run.py` (31), the `.sb` profiles.

Wire format: `sendmsg` carrying a 4-byte big-endian length **plus** `SCM_RIGHTS`
with exactly three fds, then the JSON body; reply is JSON
(`{"status":"exited","code":7}` / `{"status":"signalled","signal":15}` /
`{"status":"error","message":...}`) followed by `shutdown(SHUT_WR)`.

**One thing the spec did not anticipate.** macOS caps `sun_path` at 104 bytes.
The socket path used here is 144 bytes, so `bind`/`connect` on the absolute path
cannot work at all. Both binaries therefore call `enter_socket_dir()`, which
`chdir`s to the socket's directory and uses the bare file name. The client
captures its real cwd *before* chdir'ing, and sends that in the request. This is
not cosmetic: any agent working directory deeper than ~90 characters hits it.

## 1. Socket reachability from a deny-default sandbox

Base profile `$S/strict.sb` is exactly the one in the task. Client run as

```
cd $S/A && $S/nd7-target/debug/nd7 run --profile $S/strict.sb \
    $S/target/debug/client $S/run/broker.sock -- /bin/echo hi
```

Output:

```
client: connect .../run/broker.sock: Operation not permitted (os error 1)
exit=2
```

Adding **one** line (`$S/strict-sock.sb`):

```
(allow network-outbound (literal "/private/tmp/.../spike-broker/run/broker.sock"))
```

```
cd $S/A && nd7 run --profile $S/strict-sock.sb client $S/run/broker.sock -- \
    /bin/sh -c 'echo brokered ok; exit 5'
brokered ok
exit=5
```

That is the whole rule set. Verified *not* needed, on top of the task's
`strict.sb`:

* `file-write*` on the socket path — `strict-sock.sb` grants `file-write*` only
  under `PROJ` (`$S/A`), and the socket is at `$S/run`. `connect(2)` and
  `sendmsg` with `SCM_RIGHTS` both succeed anyway.
* `network*`, `network-bind`, `ipc-posix*`, `mach-lookup` — none added, all
  experiments pass.
* nothing extra for passing descriptors: `SCM_RIGHTS` is not separately
  filtered; the same `network-outbound` right covers the whole connected socket.

Negative control (the rule is a literal, not a blanket unix-socket allow): a
second broker on `$S/run/other.sock`, client still under `strict-sock.sb`:

```
client: connect .../run/other.sock: Operation not permitted (os error 1)
```

`(trace "...")` produced no file under `(deny default)` and macOS 15 does not
log Seatbelt denials for non-platform binaries via `log show`, so the rule set
was established by bisection rather than by trace.

Caveat: the client `chdir`s into the socket's directory, which needs the
`file-read*` already in `strict.sb`. A socket under a directory the sandbox
cannot read would fail before `connect`.

## 2. Widening works

Broker child profile `$S/broker-child.sb` = `strict.sb` +
`(allow file-write* (subpath (param "GRANT")))`; broker started with
`--grant $S/GRANT`. It passes `PROJ = request cwd` and `GRANT = the grant dir`.
Client always under `strict-sock.sb` with cwd `$S/A`.

| # | command | result |
|---|---|---|
| 2a | via broker: `sh -c 'echo hi > $S/GRANT/x'` | `exit=0`, `$S/GRANT/x` contains `hi` |
| 2b | directly in the sandbox: `nd7 run --profile strict-sock.sb sh -c 'echo hi > $S/GRANT/direct'` | `Operation not permitted`, `exit=1`, file not created |
| 2c | via broker: `sh -c 'echo hi > $S/THIRD/y'` | `/bin/sh: .../THIRD/y: Operation not permitted`, `exit=1`, file not created |
| 2d | via broker: `sh -c 'echo hi > $S/A/z'` | `exit=0` (PROJ still works) |

So the broker genuinely widens (2a vs 2b) and the brokered child is still
confined (2c) — and 2c's error text arrived on the client's own stderr, which is
the fd-passing working.

## 3. I/O fidelity

```
cd $S/A && nd7 run --profile strict-sock.sb client $SOCK -- \
  /bin/sh -c 'cat; echo err >&2; exit 7' < out/in.bin > out/out.bin 2> out/err.txt
```

* `client exit=7`
* `in.bin` and `out.bin` both 1048576 bytes,
  sha256 `f822dada6b4d80166c2f0844f971172ed5cbc6c35f769347a678da74781d9229` for
  both; `cmp` reports no difference.
* `err.txt` is exactly `err\n`.
* `sh -c 'kill -TERM $$'` → **client exit 143**. `exit 7` → 7.

The output files live in `$S/out`, outside both PROJ and GRANT: the child writes
to them through the inherited descriptor, because Seatbelt checks `open(2)`, not
`write(2)`. That is the point of passing fds, and also the main thing to be
aware of — whoever holds the client's stdout decides where brokered output
lands.

## 4. Disconnect kills

`client $SOCK -- /bin/sh -c 'sleep 100 & sleep 100'`, SIGINT to the client after
1 s, `ps` after 2 s.

**With the process group** (default: a second `pre_exec` after the sandbox one
calls `setpgid(0, 0)`; the broker kills `-pgid`):

```
  PID  PPID  PGID COMM
39360 38421 39360 /bin/sh      <- ppid = broker, own process group
39361 39360 39360 sleep
39362 39360 39360 sleep
client exit=130
after 2s: sleep 100 processes alive: 0
```

**With `--no-pgroup`** (broker kills the child pid only):

```
  PID  PPID  PGID COMM
39449 39442 39438 /bin/sh      <- pgid 39438 is the BROKER's own group
39450 39449 39438 sleep
39451 39449 39438 sleep
client exit=130
after 2s: 39450 sleep 100 / 39451 sleep 100   (ppid now 1)
```

So: grandchildren survive without the process group, and `kill(-pgid)` without
`setpgid` would have killed the broker's own group. `setpgid(0, 0)` in
`pre_exec` **is allowed under `(deny default)`** — it is not a Seatbelt-filtered
operation — and it runs after `sandbox_init_with_parameters`.

Kill latency, measured over three trials (SIGINT to last child gone):
**21.5 ms, 18.2 ms, 17.5 ms** — bounded by the watcher's 20 ms `poll` timeout.

## 5. TTY

A pty was created with `$S/pty_run.py` (`pty.fork` + `TIOCSWINSZ`); macOS
`script -q /dev/null …` could not be used because the harness's own stdin is not
a tty.

| case | `sh -c 'test -t 0 …'` through the broker |
|---|---|
| client's stdin is `/dev/null` | `notty` |
| client on a pty | `TTY-STDIN`, `TTY-STDOUT`, `tty` prints `/dev/ttys004` |

Interactive typing works end to end:

```
python3 pty_run.py --send 'Ahmed\n' client $SOCK -- /bin/sh -c 'read -p "name? " n; echo "hi $n"'
name? Ahmed
hi Ahmed
[pty_run] exit code=0
```

The line discipline echoes the typed input, so the pty is really the child's
controlling terminal end, not a pipe.

One gap, and it is **not** the broker's: `stty size` through the broker printed
`stty: TIOCGETD: Operation not permitted`. The same command under
`nd7 run --profile strict.sb` on the same pty fails identically, and with no
sandbox at all prints `24 80`. Adding `(allow file-ioctl)` to the child profile
makes it print `24 80` through the broker. So deny-default Seatbelt blocks
terminal ioctls; anything that queries window size or sets raw mode (a pager, a
progress bar, a TUI) needs `(allow file-ioctl)` in the profile — with or without
a broker.

## 6. Latency (20 sequential runs each, release build, warm)

| case | median | mean |
|---|---|---|
| direct `/usr/bin/true` | 2.70 ms | 2.81 ms |
| via broker, child under `broker-child.sb` | 18.74 ms | 19.10 ms |
| `nd7 run --profile strict.sb /usr/bin/true` (sandbox, no broker) | 20.03 ms | 20.17 ms |
| via broker, child under `(allow default)` | 14.39 ms | 17.28 ms |
| `nd7 run --profile permissive.sb /usr/bin/true` | 12.91 ms | 13.68 ms |
| sandboxed client via broker (client also pays `sandbox_init`) | 34.85 ms | 35.65 ms |

**Per-call overhead of the broker itself: ≈ 1.5 ms** (14.39 vs 12.91 on the
identical permissive profile, and the strict pair is a wash within noise). The
~16 ms that separates a brokered `true` from a direct one is almost entirely
`sandbox_init_with_parameters` compiling the profile in the child — the same
cost `nd7 run` already pays. A sandboxed client pays it twice (once for itself,
once for the brokered child): ~35 ms.

This measurement found a real bug in the first version of the prototype: the
client used `read_to_end` and therefore waited for EOF, which only arrived when
the broker's connection thread dropped the socket — after joining a watcher
thread that polls on a 20 ms timeout. Median was 39 ms. Adding
`sock.shutdown(Shutdown::Write)` right after the reply took it to 18.7 ms.

## 7. Environment and cwd

```
cd "$S/a dir with space"
MYVAR='hello there' nd7 run --profile strict-sock.sb client $SOCK -- \
  /bin/sh -c 'pwd; env | grep MYVAR; echo "argv: [$1] [$2]"' _ 'two words' 'a"quote'
```

```
/private/tmp/.../spike-broker/a dir with space
MYVAR=hello there
argv: [two words] [a"quote]
exit=0
```

`env_clear().envs(...)` plus `current_dir(cwd)` reproduce the client's
environment exactly. The space-bearing cwd is also used as the `PROJ` Seatbelt
parameter, and a write to `./file with space` in that directory succeeds, so
parameters stay data through the broker just as they do in `spawn_with_profile`.

## 8. Background processes

```
client $SOCK -- /bin/sh -c 'nohup sleep 30 >/dev/null 2>&1 &'
client returned after 0.059 s, exit=0

  PID  PPID  PGID  SESS COMMAND
42222     1 42221     0 sleep 30
```

The client returns immediately, the `sleep` survives, and its parent is **pid 1**
(launchd): its real parent was the brokered `/bin/sh`, which exited, so it was
reparented. It keeps the brokered process group (42221), which no longer has a
leader. Nothing kills it, because the watcher only fires when the client
disconnects *before* the child exits — here the child exited first.

A backgrounded job that does *not* redirect keeps the client's descriptors:
`client $SOCK -- sh -c 'sleep 25 &' | cat` returned from the client at once but
the pipe stayed open 25 s. Running `/bin/sh -c 'sleep 4 &' | cat` directly
behaves identically (4.04 s), so this is faithful shell behaviour, not a broker
artifact.

## (a) Minimal SBPL the outer (client) profile needs for the socket

On top of the task's `strict.sb`, exactly one rule:

```
(allow network-outbound (literal "<absolute socket path>"))
```

Nothing else. Not `file-write*` on the socket, not `network*`, not `ipc-posix*`.
The `file-read*` already in `strict.sb` is what lets the client `chdir` into the
socket's directory (needed only because of the 104-byte `sun_path` limit).

Separately, if brokered commands should be able to use a terminal properly, the
**child** profile needs `(allow file-ioctl)` — a pre-existing `nd7 run` gap, not
a broker one.

## (b) What worked as expected

* Widening: a brokered child gets write access the client does not have (2a/2b),
  while still being confined by the broker's own profile (2c). The core premise
  holds.
* Descriptor passing: 1 MB through stdin byte-exact, stderr separate, exit codes
  and signals (`exit 7` → 7, SIGTERM → 143) all faithful.
* A real pty survives the hop: `isatty(0)`/`isatty(1)`, `tty`, and interactive
  `read -p` with typed input all behave as if the command ran locally.
* Disconnect kill with `setpgid(0,0)` + `kill(-pgid)`: whole tree gone in
  ~20 ms. `setpgid` is not blocked by `(deny default)`.
* cwd, argv and environment round-trip exactly, spaces and quotes included.
* Backgrounded jobs behave exactly as they do without the broker.
* Overhead is ~1.5 ms; the cost of a brokered call is dominated by
  `sandbox_init`, which is paid anyway.

## (c) What did not work, or needs care

1. **104-byte socket path.** Not a detail: the natural socket location under a
   deep project directory is unusable. Both ends must `chdir` and bind/connect a
   bare name. A production version should put the socket somewhere short
   (`$TMPDIR/nd7-<id>.sock`) and still keep the chdir trick as insurance.
2. **Terminal ioctls are denied** by the deny-default profile (`TIOCGETD`), so
   `stty`, window-size queries and raw mode fail. Fixed by `(allow file-ioctl)`.
   Pre-existing in `nd7 run`.
3. **Two latency/correctness bugs the experiments exposed** in the first draft:
   the client waiting for socket EOF instead of a framed reply (+20 ms per
   call), and a race where the watcher could `kill` a pid the main thread had
   already reaped. Fixed with `shutdown(SHUT_WR)` and a `Mutex<bool>` held
   across both the kill and the reap. Any real implementation will hit both.
4. **`(allow file-ioctl)` aside, the widening grant is coarse.** The broker
   applies one fixed profile to every request; the client cannot ask for less.
   A real design wants a per-request policy chosen by the broker, which is the
   interesting follow-up.
5. **The peer-uid check is untested.** `getpeereid` is called and compared with
   `geteuid`, but connecting as another uid needs an interactive `sudo`
   password, so the reject path was never exercised.
6. **Backgrounded jobs escape the kill switch** (experiment 8): once the direct
   child exits, the process group has no leader and nothing reaps the survivors.
   That is what a user wants from `&`, but it means "client dies → all brokered
   work dies" is only true for work that is still in the foreground.
7. **Anyone who can reach the socket gets the wider profile.** The socket *is*
   the privilege. Same-uid is the only check; any process of the same user,
   sandboxed or not, can use it if its profile names the path.

# Spike E: Codex CLI under `nd7 run`

2026-09-22. Codex CLI 0.155.1 (standalone install, `~/.local/bin/codex` -> `~/.codex/packages/standalone/...`),
macOS Darwin 25.6, nd7 at 71b845d. 11 Codex model turns; everything else measured without a model call.
Nothing in this repo changed for the spike. Raw streams, profiles and hook scripts were kept in the session
scratchpad; the facts that matter are here.

## Headline
Codex needs no new nd7 mechanism. Its `PreToolUse` hook payload and reply schema are Claude Code's, its
`tool_name` for shell calls is `"Bash"`, and the unchanged `nd7 hook-prefix` rewrites Codex's commands to
`nd7-exec -c '<cmd>'`, which then run under the session policy. `nd7 allow` reaches them. What Codex needs:
1. one more write root in the floor, `~/.codex` (its `~/.claude`), with `config.toml` and `auth.json` deniable
   inside it by the same last-wins per-operation deny used for `~/.nd7`;
2. `-s danger-full-access` so it does not try to apply its own Seatbelt profile (identical in effect to
   `--dangerously-bypass-approvals-and-sandbox`, but leaves `approval_policy` alone for the TUI);
3. `--dangerously-bypass-hook-trust`, because hooks passed with `-c` carry no persisted trust hash;
4. `-c developer_instructions="<note>"` as the `--append-system-prompt` analogue (verified with
   `codex debug prompt-input`; `instructions=` does NOT reach the prompt).

## Codex's own sandbox (E2, no model calls)
Seatbelt via `/usr/bin/sandbox-exec` exec'd by ABSOLUTE path (no PATH lookup to interpose on); profile is
Chrome-derived, templated roots, and with network on it allows all ports and hosts. `codex sandbox --log-denials`
finds nothing even for real denials (same `log` unreliability as spike D). Under the nd7 floor the failure is
`sandbox-exec: sandbox_apply: Operation not permitted`, exit 71, printed by sandbox-exec itself.

## Under the floor (E3)
- Startup fails before any model call without `~/.codex` writes: "failed to initialize in-process app-server
  client: Operation not permitted". Bisected with a dead model provider (free): the whole `~/.codex` tree is
  needed; `config.toml` and `auth.json` may be denied and Codex still starts and runs. Caveat: a ChatGPT token
  refresh that rewrites `auth.json` would fail; not observed in ~11 runs; drop that deny if it shows.
- Nothing else needed: no new mach-lookup, no port beyond 443, no unix socket, no network-bind.
- Default mode (`read-only`): the model never attempts a write command. `-s workspace-write`: the veto; Codex
  reports "the shell sandbox failed with sandbox_apply: Operation not permitted", exits 0, does NOT retry
  unsandboxed and does NOT disable its sandbox for the session. Fail-closed. The failed call produces NO
  `command_execution` item in `--json`.
- `-s danger-full-access` (or the bypass flag): commands run directly under the floor. Probes: project write
  ok; `$HOME` write "operation not permitted"; nested `sandbox-exec` refused (71). Codex's own turn_context says
  `sandbox_policy: danger-full-access`, i.e. "externally sandboxed", which is what the flag's help text names.
- Full trampoline with a patched floor (+`~/.codex`) and `nd7 hook-prefix` as the hook: the command that ran was
  `/bin/zsh -lc "<nd7-exec> -c 'id -un ; echo x > $HOME/nd7_probe2'"`, output `ahmedabouzied` then
  `operation not permitted`. `nd7 allow` widened the next call (DENIED-EARLY -> GRANTED-LATE).

## Hooks (E4)
Feature `hooks` stable and on by default. Events: PreToolUse, PermissionRequest, PostToolUse, PreCompact,
PostCompact, SessionStart, SessionEnd, UserPromptSubmit, SubagentStart, SubagentStop, Stop, Interrupt.
Config (TOML) `[[hooks.PreToolUse]] matcher="" [[hooks.PreToolUse.hooks]] type="command" command="..." timeout=30`;
handler types command | mcp_tool | prompt | agent (prompt/agent "not supported yet"). Discovery:
`$CODEX_HOME/config.toml`, `$CODEX_HOME/hooks.json`, `./hooks.json`, `.codex/hooks.json`, plugins, MDM
`hooks.managed_dir`; `allow_managed_hooks_only` can forbid `-c` hooks on managed machines. `-c hooks.PreToolUse=[...]`
works per invocation with `--dangerously-bypass-hook-trust` (two advisory `error` items, then runs).
Payload = Claude Code's schema (`session_id`, `cwd`, `hook_event_name`, `tool_name:"Bash"`, `tool_input.command`,
`tool_use_id`) plus `turn_id`; `permission_mode:"bypassPermissions"`; PostToolUse `tool_response` is a STRING;
`transcript_path` null under `--ephemeral`. `apply_patch` is its own `tool_name` with the patch envelope in
`tool_input.command`, and runs inside the codex process (sees only the floor, like Claude's Write/Edit).
Rewrite via `hookSpecificOutput.updatedInput` honoured; `permissionDecision:"deny"` blocks with the reason shown
to the model. Codex runs commands with the SYSTEM `/bin/zsh -lc "<cmd>"`, not its vendored zsh, not `$SHELL`.

## Recording source (E5)
- `--json` stdout: rejected. Blocked or sandbox-failed calls emit no item; `command` is the `zsh -lc` wrapper;
  exec-only.
- Rollout JSONL (`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`): internal format; with code_mode a shell call is
  a JavaScript program calling `tools.exec_command(...)`; no exit code; absent under `--ephemeral`.
- Hooks: the source. Normalised, complete, fires before and after, present in exec and TUI, and already the
  shape `hook::HookInput` parses. No new parser; tolerate `turn_id`, string `tool_response`, null
  `transcript_path`; consider a `source: codex|claude` discriminator on frames.

## Change list
- policy.rs: add `(require-all (subpath HOME) (regex #"/\.codex(/|$)"))` to the write rule; extend the trailing
  per-op deny (or a sibling) to `~/.codex/config.toml` and `~/.codex/auth.json`.
- nd7.rs: resolve `program` (PATH lookup + canonicalize) before matching the basename; add `codex_flags()`:
  `-s danger-full-access`, `--dangerously-bypass-hook-trust`,
  `-c hooks.PreToolUse=[{matcher="", hooks=[{type="command", command="<nd7> hook-prefix", timeout=30}]}]`,
  `-c developer_instructions=<TOML string of the nd7 note>`; for `codex exec` add `-c approval_policy="never"`
  at the call site when unattended.
- hook_prefix.rs: no change; doc sentence that it serves both agents.
- record: accept Codex payloads as they are; check the three field differences against hook.rs.
- README/ADR: `nd7 run codex`, the `~/.codex` root, the flags, limits (`apply_patch` floor-only;
  `allow_managed_hooks_only` machines).

## Free probes worth keeping
- Startup-only: `-c 'model_providers.fake={name="fake", base_url="https://127.0.0.1:1/v1", wire_api="responses",
  requires_openai_auth=false}' -c model_provider="fake" -c model="x"` (fails on connect after full init).
- Schema: `codex features list -c '<key>=<value>'` prints serde's "unknown variant … expected one of …".
- Prompt: `codex debug prompt-input -c … "<prompt>"` prints the model-visible input.

## Side effects
Codex appended a `[projects."…/spike-codex/proj"] trust_level = "trusted"` block to `~/.codex/config.toml`
(line 56); left for the user to remove. Spike sessions were deleted with `codex delete --force`. No probe files
remain under `$HOME`.
